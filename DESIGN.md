# DESIGN.md — CodeArchaeologist

> The single source of visual truth. Read it before changing any UI. For *what* to build and *why*, read
> [PRODUCT.md](PRODUCT.md). If something is not defined here, extend this document before inventing a style.

**Direction:** *Evidence Console*. A black engineering canvas with precise white chrome—hairlines and compact
typography—where color appears only with meaning: signal orange for the primary action, the risk spectrum for
severity, and green for verified results. Inspired by linearity.io, adapted to a dense daily-use tool rather
than a landing page.

- Original reference, not used directly: [docs/design/reference/](docs/design/reference/).
- Implementation: [frontend/src/styles/tokens.css](frontend/src/styles/tokens.css) for tokens and
  [frontend/src/components/](frontend/src/components/) for primitives and domain components.

---

## 1. Principles

1. **Black is the workspace.** Use the `void` canvas throughout the app. No light sections or white cards.
2. **Separate with lines, not shadows.** Use 1px white at 10%; no floating elevation.
3. **Color means something.** Orange is only for each screen's primary action and Bob's send orb. Severity
   and verification use their own scales. Never use color as decoration.
4. **Density with hierarchy.** Body text is 14px, controls 12px, and eyebrows 10px. Space creates hierarchy,
   not emptiness.
5. **Evidence first.** Show `file:line` paths in monospace, always clickable, with verified/unverified state.
6. **Never color alone.** Every state also carries text and/or a glyph (◆ ▲ ● ○ ✓ ✗).

## 2. Tokens

There are three layers. Components use **semantic tokens only** through Tailwind classes generated by
`@theme`. Primitives exist as `--ca-*` variables and intentionally do not generate utilities.

```text
Primitive (--ca-void)  →  Semantic (--color-canvas → bg-canvas)  →  Component (Button primary)
```

### 2.3 Typography

| Family | Token | Use |
|---|---|---|
| Space Grotesk Variable, an AcidGrotesk substitute | `font-display` | titles, **always weight 400** |
| Inter Variable | `font-sans` | UI and body |
| JetBrains Mono Variable | `font-mono` | code, paths, IDs, technical figures |

Fonts are self-hosted with `@fontsource-variable/*`; there is no CDN.

| Utility | Size / line height | Use |
|---|---|---|
| `text-micro` | 10px / 1.4, `tracking-eyebrow` (0.14em), uppercase | eyebrows and table headings |
| `text-caption` | 12px / 1.5 | controls, buttons, metadata |
| `text-body` | 14px / 1.5 | body and navigation |
| `text-title` | 17px / 1.3 display | panel titles |
| `text-heading` | 21px / 1.25 display | screen title |
| `text-display` | 34px / 1.2 display, -0.01em | Projects screen only |
| `text-code` | 12px / 1.7 mono | code |

Use `tabular-nums` for figures, `text-balance` for short titles, and `text-pretty` for descriptions.

### 2.4 Spacing, radii, shadows, and motion

- **Spacing:** 4px base from the default Tailwind scale. Common rhythm: 4 · 8 · 12 · 16 · 24 · 56.
- **Radii:** concentric, where outer radius equals inner radius plus padding.

| Utility | Value | Use |
|---|---|---|
| `rounded-pill` | 9999px | buttons, chips, segmented controls, search |
| `rounded-panel` | 12px | panels, popovers, palette |
| `rounded-inner` | 8.57px | panel contents and code blocks |
| `rounded-composer` | 17.14px | Bob composer and upload area |
| `rounded-tick` | 2.57px | tiny markers |

- **Shadows:** none except `shadow-glow` for the primary button's yellow halo, `shadow-inset-accent` for a 1px
  ember inset on strong selection, and `shadow-pop` for popovers and the palette only.
- **Motion:** 150ms `ease-out` on hover/press using
  `transition-[color,background-color,border-color,box-shadow,transform]`; 200ms opacity + translate when
  opening panels. Never use `transition-all`. `prefers-reduced-motion` disables nonessential animations in
  `tokens.css`.

### 2.5 Visual signature: *Spectrum Rail*

The `bg-spectrum` gradient runs green → orange → red → violet. Use it **only** as a 2px line:

- the animated status rail while Bob analyzes; stop it under reduced motion;
- the underline beneath one phrase on the Projects screen.

Never use it as a background, text fill, or panel border.

## 3. Layout: app shell

```text
┌ TopBar 48px: brand · project selector · ⌘K · Bob status · AI toggle ─────────────────┐
├ NavRail 224px ┬ Workspace (own scroll, 24px padding) ┬ AI panel 360px ──────────────┤
│ bg-surface    │ bg-canvas                            │ bg-surface, collapsible (⌘J)│
├───────────────┴──────────────────────────────────────┴───────────────────────────────┤
└ StatusBar 28px: analysis stage · mode · backend · Bob · sha ────────────────────────┘
```

- Below `lg`, NavRail becomes a menu-button drawer and the AI panel becomes a right drawer, closed on load.
- **Views respond to workspace width, not viewport width.** `<main>` is an `@container`; internal grids use
  container variants such as `@3xl:grid-cols-2` and `@4xl:...`. This keeps layouts responsive when the Bob
  panel opens. Do not use `lg:` or `xl:` inside `views/`.
- **Every breakpoint-based grid starts with `grid-cols-1`**, for example
  `grid grid-cols-1 @3xl:grid-cols-2`. Without it, the implicit column takes the minimum content width and a
  code block with `min-w-max` or a long path pushes the workspace sideways. This previously affected
  Repository and Risks with the Bob panel open.
- **Live content never moves the page.** Lists that grow while Bob works—the feed, `BobWork`, and chat—scroll
  only their own container and only when the user was already at the end. Never call `scrollIntoView`.
- URL hash state is navigable:
  `#/p/<job>/<section>?f=F-1&file=app.py&line=78&node=<id>&play=1`. `play=1` replays the session on open and is
  used by the showcase.
- Views use hairline-separated sections, tables, lists, trees, graphs, and split panes. Reserve cards for real
  objects such as a finding or downloadable file.

Console rules:

- Work in progress uses the pulsing white `activity` token. Completed work uses `verified`. Orange never means state.
- Recorded sessions are labeled **Real recorded IBM Bob session…**.
- Never show repository file contents in the feed—only relative paths, titles, and summaries.

## 5. Accessibility

- Contrast: normal text ≥ 4.5:1. Never use `--ca-ash` for text. Visible focus is a 2px ember ring with 2px offset.
- Semantics: `nav`, `main`, `aside`, `header`; tables use `th`; dialogs use `role="dialog"`, `aria-modal`, a
  focus trap from `components/ui/useFocusTrap.ts`, and an `inert` background. Segmented controls have one Tab
  stop plus arrow-key navigation. SVG nodes have `tabIndex` and their own focus ring.
- Do not declare composite ARIA roles such as `tree`, `grid`, or `menu` without implementing their full
  keyboard model. Prefer lists and buttons.
- Every control works with a keyboard. Shortcuts: ⌘K opens the palette, ⌘J toggles the AI panel, Esc closes.
- State is never color alone. Use `aria-live="polite"` for analysis state and Bob responses.

## 6. Do not

- Use background gradients, glows outside the primary button, glassmorphism, generic AI purple, or sparkles.
- Apply generic `rounded-xl` everywhere, nest cards, or default to three metric cards in a row.
- Add arbitrary values such as `bg-[#111]`, `text-[13px]`, or `rounded-[10px]` when a token exists.
- Use signal orange as a surface fill or severity color.
- Display unsourced figures. Every figure comes from the backend dossier, graph, or architecture data. If data
  is unavailable, say so.

## 7. How to extend the system

1. Does a semantic token exist? Use it. If not, add it to `tokens.css` from primitive → semantic and document it here.
2. Does a primitive exist in `components/ui`? Compose it before creating another.
3. For a new domain component, add a one-line role to the §4 table.
