# Evidence Standards for Legacy Findings

> Every finding produced by any agent in the CodeArchaeologist ecosystem MUST include verifiable evidence grounded in source code.

## Mandatory Evidence Schema
Every finding emitted must populate the `evidence` object with these exact fields:
- `file`: Exact relative path of a file that actually exists in the repository.
- `line_start`: Positive 1-indexed integer indicating the first line of relevant code.
- `line_end`: Positive 1-indexed integer ($\ge \text{line\_start}$) indicating the final line.
- `snippet`: The verbatim code snippet extracted from those exact lines.
- `observed_or_inferred`: String enum, either `"observed"` (directly visible in source text) or `"inferred"` (deduced through static analysis or call hierarchy).

## Acceptable Evidence
1. **Direct Syntactic Evidence**: String concatenation in queries, hardcoded credentials, bare `except:` clauses, `debug=True`.
2. **Static Analysis Artifacts**: AST parsed complexity scores, import matrices, cyclomatic counts generated by code tools.
3. **Configuration & Manifest Entries**: Outdated dependency versions pinned in `requirements.txt`.

## Unacceptable / Disallowed Material
1. **Speculative Claims**: "There is probably a memory leak in the billing module" without showing the leaked resource.
2. **Unattributed Metrics**: Stating "risk is 8/10" or "effort is 40 hours" without showing formula and parameters.
3. **Stale References**: Citing line numbers from past versions or hallucinated files.
4. **Any finding lacking an exact line reference will be discarded by the validation filter.**
